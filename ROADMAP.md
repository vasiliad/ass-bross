# ROADMAP: ЭТАПЫ РАЗРАБОТКИ
**Проект:** Сверхлегкий веб-браузер (NanoWeb)
**Платформа:** Windows 10/11 x64
**Цель:** качественный сёрфинг по сайтам с содержимым и максимально быстрый разбор страниц. JavaScript, аудио и видео не поддерживаются (`ARCHITECTURE.md`, раздел 9).

Разработка разбита на изолированные инженерные вехи (Milestones). Каждая веха заканчивается проверяемым результатом и автоматическими тестами.

Порядок выбран так, чтобы движок не зависел от сети: этапы M1–M3 работают с локальными HTML-файлами. Это упрощает отладку и тестирование; сеть подключается, когда разбор и отрисовка уже стабильны.

**MVP = M0–M6.**

---

## Milestone 0: Инфраструктура
* Структура каталогов и сборка (`build.bat` для Windows, `Makefile` для сборки на Linux + запуск через Wine).
* `src/include/structs.inc` — определения всех структур из `MEMORY_MODEL.md`.
* Отладочный вывод: `dbg_print_str`, `dbg_print_int`, `dbg_print_hex` (stdout + `OutputDebugStringW`).
* Разбор аргументов командной строки (`GetCommandLineW`).
* Тестовый стенд: pytest запускает `nanoweb.exe` в режимах дампа и сравнивает вывод с эталонными файлами (golden tests).
* Бенчмарк-стенд: режим `--bench`, корпус сохранённых реальных страниц в `tests/bench/`, таблица результатов по коммитам.
* Git, CI (GitHub Actions, `windows-latest`: сборка + тесты).
  * *Критерий приемки:* `nanoweb.exe --version` печатает версию; CI зелёный; тестовый стенд проходит пустой эталонный тест.

## Milestone 1: Память и быстрый разбор HTML
* **Арены:** `arena_init`, `arena_alloc`, `arena_reset`, `arena_release` (резерв + фиксация по 64 КБ).
* **Загрузка файла** в `src_arena`; определение кодировки (UTF-8, windows-1251).
* **HTML Tokenizer:** возобновляемый конечный автомат (таблица переходов) для поддерживаемого подмножества (`ARCHITECTURE.md`, раздел 6); SIMD-сканирование текста (SSE2, AVX2 по `CPUID`); числовые и основные именованные сущности.
* **Таблицы имён:** совершенный хэш для тегов и атрибутов, генерируемый при сборке.
* **DOM Builder:** дерево `DOM_NODE`, void-элементы, неявное закрытие тегов, восстановление после ошибок разметки (программа не падает на любом входе).
* Режимы `--dump-dom <file>` и `--bench parse <file>`.
  * *Критерий приемки:* golden-тесты на наборе страниц из `tests/pages/`; выбранные случаи из html5lib-tests проходят; разбор случайных/битых файлов не приводит к падению; **скорость HTML → DOM ≥ 200 МБ/с** на корпусе `tests/bench/`.

## Milestone 2: Стили и компоновка
* **CSS Parser:** UA stylesheet (встроен в exe), `<style>`, атрибут `style=""`.
* **Style Resolver:** селекторы (с корзинами по тегу/классу/id), каскад, специфичность, `!important`, наследование → `COMPUTED_STYLE`.
* **Измерение текста** через `SysFont` (GDI работает и без окна, через memory DC), с кэшем ширин символов.
* **Layout Engine:** блочная компоновка (margin/padding/border, `width`/`height`, `auto`), анонимные блоки, строчная компоновка с переносом по словам, `text-align`.
* Режимы `--dump-style`, `--dump-layout <file> [--width N]`, `--bench style|layout`.
  * *Критерий приемки:* вывод дерева координат (`BLOCK div: X=0 Y=50 W=800 H=200`) совпадает с эталонами; эталоны для простых страниц сверены с Chrome/Firefox (допуск ±1 px без учёта текста).

## Milestone 3: Окно и отрисовка
* **SysGUI:** окно, DIB-буфер, DPI-awareness, цикл сообщений.
* **Painter:** фоны, рамки, текст (цвет, жирный, курсив, подчёркивание).
* **Прокрутка:** колесо мыши, клавиши (стрелки, PgUp/PgDn, Home/End), полоса прокрутки.
* **Resize:** пересчёт компоновки при изменении размера окна.
* Открытие локального файла: `nanoweb.exe page.html`.
* Режим `--stats`: время старта, время этапов, Private Bytes.
  * *Критерий приемки:* тестовые страницы отображаются корректно (скриншоты сверены вручную, затем фиксируются как эталоны); холодный старт < 20 мс; Private Bytes < 2 МБ без страницы.

## Milestone 4: Сеть (HTTP)
* **URL:** разбор, относительные ссылки, `file://`.
* **SysNet:** `getaddrinfo`, неблокирующий TCP через `WSAAsyncSelect`.
* **NetClient:** HTTP/1.1, `Content-Length`, chunked, редиректы, кодировка из `Content-Type`.
* **Потоковый разбор:** HTML разбирается по мере прихода пакетов.
* Загрузка `<link rel="stylesheet">`.
* Встроенные страницы ошибок (нет соединения, 404).
  * *Критерий приемки:* `nanoweb.exe http://example.com` отображает страницу; набор тестов против локального сервера (`python -m http.server` + сервер с chunked/редиректами/медленной отдачей) проходит; интерфейс не замирает во время загрузки.

## Milestone 5: HTTPS
* **SysTLS:** TLS 1.2/1.3 через SChannel (`AcquireCredentialsHandle`, цикл `InitializeSecurityContext`, `EncryptMessage`/`DecryptMessage`).
* Проверка сертификатов средствами Windows; страница предупреждения при ошибке.
* Состояние `TLS_HANDSHAKE` в автомате NetClient.
  * *Критерий приемки:* открываются https-сайты из тестового набора; просроченный и самоподписанный сертификаты (badssl.com) корректно отклоняются.
  * *Проверка риска:* выдача DuckDuckGo Lite открывается без капчи. Если капча появляется регулярно — минимальные `<img>` и формы переносятся в MVP (`ARCHITECTURE.md`, раздел 11.1).

## Milestone 6: Навигация (завершение MVP)
* Адресная строка (стандартный `EDIT`-контрол Windows).
* Hit-testing: клик по ссылке, курсор-рука при наведении, строка состояния с адресом ссылки.
* История: Назад/Вперёд (`Alt+←`/`Alt+→`, `Backspace`), обновление (`F5`).
* Заголовок окна из `<title>`.
* **Поиск из адресной строки:** шаблоны и префиксы из `nanoweb.ini` (по умолчанию DuckDuckGo Lite, `w` — Википедия).
* **Marginalia через API** (префикс `m`): минимальный JSON-парсер, встроенная страница результатов, ключ из `nanoweb.ini` (по умолчанию `public`), обработка `503`.
* Распознавание страниц-заглушек антибот-защиты и предложение другого поисковика.
* **Поиск по странице (Ctrl+F):** SIMD-поиск подстроки по текстовым узлам, без учёта регистра (латиница и кириллица), подсветка, F3 / Shift+F3.
  * *Критерий приемки:* по тестовому набору сайтов можно перемещаться по ссылкам и назад; запрос из адресной строки открывает выдачу DuckDuckGo Lite, запрос `m …` — страницу результатов Marginalia из API; Ctrl+F находит все вхождения на странице 1 МБ быстрее 5 мс; все KPI из `ARCHITECTURE.md` (раздел 8) выполнены и зафиксированы в отчёте.

## После MVP (порядок предварительный)

### M7: Сжатие и изображения
* Собственный inflate (gzip/deflate) → `Accept-Encoding: gzip` (меньше трафика — быстрее загрузка).
* Изображения PNG/JPEG/GIF через WIC; `width`/`height` у `<img>`, резервирование места до загрузки.

### M8: Cookies и формы
* Хранение и отправка cookies.
* Формы: `<input>`, `<textarea>`, `<button>`, отправка `GET`/`POST` — вход на форумы и поиск на сайтах без JS.

### M9: Расширение CSS
* `position`, `z-index`, `float`, flexbox, `max-width`, `line-height`, веб-шрифты — в объёме, нужном тестовому набору сайтов.

### M10: История и закладки
* История посещений и закладки, подсказки в адресной строке (SIMD-поиск подстроки).

### M11: Скорость загрузки
* Keep-alive, параллельная загрузка CSS и изображений, вкладки.
* AVX2/AVX-512 пути для горячих циклов по результатам профилирования.
