# ROADMAP: ЭТАПЫ РАЗРАБОТКИ
**Проект:** Сверхлегкий веб-браузер (NanoWeb)
**Платформа:** Windows 10/11 x64

Разработка разбита на изолированные инженерные вехи (Milestones). Каждая веха заканчивается проверяемым результатом и автоматическими тестами.

Порядок выбран так, чтобы движок не зависел от сети: этапы M1–M3 работают с локальными HTML-файлами. Это упрощает отладку и тестирование; сеть подключается, когда разбор и отрисовка уже стабильны.

**MVP = M0–M5.**

---

## Milestone 0: Инфраструктура
* Структура каталогов и сборка (`build.bat` для Windows, `Makefile` для сборки на Linux + запуск через Wine).
* `src/include/structs.inc` — определения всех структур из `MEMORY_MODEL.md`.
* Отладочный вывод: `dbg_print_str`, `dbg_print_int`, `dbg_print_hex` (stdout + `OutputDebugStringW`).
* Разбор аргументов командной строки (`GetCommandLineW`).
* Тестовый стенд: pytest запускает `nanoweb.exe` в режимах дампа и сравнивает вывод с эталонными файлами (golden tests).
* Git, CI (GitHub Actions, `windows-latest`: сборка + тесты).
  * *Критерий приемки:* `nanoweb.exe --version` печатает версию; CI зелёный; тестовый стенд проходит пустой эталонный тест.

## Milestone 1: Память и DOM
* **Арены:** `arena_init`, `arena_alloc`, `arena_reset`, `arena_release` (резерв + фиксация по 64 КБ).
* **Загрузка файла** в `src_arena`; определение кодировки (UTF-8, windows-1251).
* **HTML Tokenizer:** конечный автомат для поддерживаемого подмножества (`ARCHITECTURE.md`, раздел 6), числовые и основные именованные сущности.
* **DOM Builder:** дерево `DOM_NODE`, void-элементы, неявное закрытие тегов, восстановление после ошибок разметки (программа не падает на любом входе).
* Режим `--dump-dom <file>` — вывод дерева в консоль.
  * *Критерий приемки:* golden-тесты на наборе страниц из `tests/pages/`; выбранные случаи из html5lib-tests проходят; разбор случайных/битых файлов не приводит к падению.

## Milestone 2: Стили и компоновка
* **CSS Parser:** UA stylesheet (встроен в exe), `<style>`, атрибут `style=""`.
* **Style Resolver:** селекторы, каскад, специфичность, `!important`, наследование → `COMPUTED_STYLE`.
* **Измерение текста** через `SysFont` (GDI работает и без окна, через memory DC).
* **Layout Engine:** блочная компоновка (margin/padding/border, `width`/`height`, `auto`), анонимные блоки, строчная компоновка с переносом по словам, `text-align`.
* Режимы `--dump-style` и `--dump-layout <file> [--width N]`.
  * *Критерий приемки:* вывод дерева координат (`BLOCK div: X=0 Y=50 W=800 H=200`) совпадает с эталонами; эталоны для простых страниц сверены с Chrome/Firefox (допуск ±1 px без учёта текста).

## Milestone 3: Окно и отрисовка
* **SysGUI:** окно, DIB-буфер, DPI-awareness, цикл сообщений.
* **Painter:** фоны, рамки, текст (цвет, жирный, курсив, подчёркивание).
* **Прокрутка:** колесо мыши, клавиши (стрелки, PgUp/PgDn, Home/End), полоса прокрутки.
* **Resize:** пересчёт компоновки при изменении размера окна.
* Открытие локального файла: `nanoweb.exe page.html`.
* Режим `--stats`: время старта, время этапов, Private Bytes.
  * *Критерий приемки:* тестовые страницы отображаются корректно (скриншоты сверены вручную, затем фиксируются как эталоны); холодный старт < 20 мс; Private Bytes < 2 МБ без страницы.

## Milestone 4: Сеть
* **URL:** разбор, относительные ссылки, `file://`.
* **SysNet:** `getaddrinfo`, неблокирующий TCP через `WSAAsyncSelect`.
* **NetClient:** HTTP/1.1, `Content-Length`, chunked, редиректы, кодировка из `Content-Type`.
* Загрузка `<link rel="stylesheet">`.
* Встроенные страницы ошибок (нет соединения, 404, HTTPS ещё не поддерживается).
  * *Критерий приемки:* `nanoweb.exe http://example.com` отображает страницу; набор тестов против локального сервера (`python -m http.server` + сервер с chunked/редиректами) проходит; интерфейс не замирает во время загрузки.

## Milestone 5: Навигация (завершение MVP)
* Адресная строка (стандартный `EDIT`-контрол Windows).
* Hit-testing: клик по ссылке, курсор-рука при наведении, строка состояния с адресом ссылки.
* История: Назад/Вперёд (`Alt+←`/`Alt+→`, `Backspace`), обновление (`F5`).
* Заголовок окна из `<title>`.
  * *Критерий приемки:* по тестовому набору сайтов на HTTP можно перемещаться по ссылкам и назад; все KPI из `ARCHITECTURE.md` (раздел 8) выполнены и зафиксированы в отчёте.

## После MVP (порядок предварительный)

### M6: HTTPS
* TLS через SChannel (`AcquireCredentialsHandle`, цикл `InitializeSecurityContext`, `EncryptMessage`/`DecryptMessage`).
* Проверка сертификатов средствами Windows.
* *Критерий:* открываются https-сайты из тестового набора (Википедия в мобильной версии, текстовые новостные сайты).

### M7: Сжатие и изображения
* Собственный inflate (gzip/deflate) → `Accept-Encoding: gzip`.
* Изображения PNG/JPEG/GIF через WIC; `width`/`height` у `<img>`.

### M8: Медиа
* `<audio>` и `<video>` с прямыми ссылками на файлы через Media Foundation (`IMFMediaEngine`).
* Элементы управления: воспроизведение/пауза, громкость, перемотка.
* *Критерий:* воспроизводятся MP3 и MP4 (H.264/AAC) по ссылке со страницы.

### M9: Расширение CSS
* `position`, `z-index`, `float`, flexbox, `max-width`, `line-height`, веб-шрифты (по ситуации).

### Исследование: JavaScript
* Оценка вариантов: собственный интерпретатор подмножества JS на ASM или встраивание существующего движка.
* YouTube и другие тяжёлые веб-приложения — долгосрочный ориентир, не обязательство (см. `ARCHITECTURE.md`, раздел 9).
