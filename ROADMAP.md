# ROADMAP: ЭТАПЫ РАЗРАБОТКИ
**Проект:** Сверхлегкий веб-браузер (NanoWeb)
**Платформа:** Windows 10/11 x64
**Цель:** качественный сёрфинг по сайтам с содержимым в режиме чтения и максимально быстрый разбор страниц. JavaScript, аудио, видео и воспроизведение дизайна сайтов не поддерживаются (`ARCHITECTURE.md`, раздел 13).

Разработка разбита на изолированные инженерные вехи (Milestones). Каждая веха заканчивается проверяемым результатом и автоматическими тестами.

Порядок выбран так, чтобы движок не зависел от сети: этапы M1–M3 работают с локальными HTML-файлами. Сеть подключается, когда разбор и отображение уже стабильны.

**MVP = M0–M5.**

## Milestone 0: Инфраструктура — ✅ выполнено (2026-10-01)
* Структура каталогов и сборка (`build.bat` для Windows, `Makefile` для сборки на Linux + запуск через Wine).
* **Заголовок PE:** `format PE64 NX GUI 6.0`, секция перемещений, флаги ASLR (`tools/patch_pe.py` после сборки; проверить и вариант с `store`), стек 1 МБ, манифест (Per-Monitor V2 DPI, `comctl32` v6) — `ARCHITECTURE.md`, раздел 12.
* `src/include/structs.inc` — определения всех структур из `MEMORY_MODEL.md` с проверкой размеров при сборке.
* Отладочный вывод: `dbg_print_str`, `dbg_print_int`, `dbg_print_hex` (stdout + `OutputDebugStringW`); векторный обработчик сбоев (фатальные коды, адрес внутри образа) с записью `crash.log`.
* Разбор аргументов командной строки (собственный, по `GetCommandLineW`), чтение `nanoweb.ini`.
* Тестовый стенд: pytest запускает `nanoweb.exe` в режимах дампа и сравнивает вывод с эталонными файлами (golden tests).
* Бенчмарк-стенд: режим `--bench`, корпус сохранённых реальных страниц в `tests/bench/`, таблица результатов по коммитам.
* CI (GitHub Actions, `windows-latest`): сборка, тесты, проверка флагов PE и размера exe.
  * *Критерий приемки:* `nanoweb.exe --version` печатает версию; CI зелёный; флаги ASLR/DEP подтверждены проверкой в CI; тестовый стенд проходит пустой эталонный тест.
  * *Итог:* exe 8,7 КБ; 22 теста на Windows в CI (версия, справка, разбор аргументов, `nanoweb.ini` в UTF-8 с BOM и CRLF, бенчмарк, журнал сбоев); загрузка с ASLR подтверждена (образ загружается не по базовому адресу).

## Milestone 1: Память и быстрый разбор HTML
> **Ход работ M1:** ✅ арены (`hal/win64/mem.inc`, `core/arena.inc`, `--selftest arena`; исполнение — на Windows/CI). Далее: `.pdata`/`proc`, загрузка файла и кодировки, токенизатор, DOM Builder, фаззер.

* **Таблица `.pdata`:** макросы `proc` с прологом без `rbp` (`static_rsp_prologue`) и автоматической записью `RUNTIME_FUNCTION`/`UNWIND_INFO`; проверка в CI, что стек раскручивается (тест со сбоем внутри WinAPI). До WinHTTP (M4) — обязательно.
* **Арены:** `arena_init`, `arena_alloc`, `arena_ensure`, `arena_advance`, `arena_reset` (обнуление первого блока: целиком у `AF_NET_TARGET`, до `Ptr` у остальных; декоммит остального), `arena_release`; тесты инварианта обнулённости.
* **Загрузка файла** в `raw` и перенос в `src` порциями; кодировки: BOM, `<meta charset>`, UTF-8 (с заменой невалидных последовательностей на U+FFFD), windows-1251, windows-1252, KOI8-R; перезапуск разбора при позднем `<meta charset>`.
* **HTML Tokenizer:** возобновляемый конечный автомат (таблица переходов); SIMD-сканирование (SSE2, AVX2 по `CPUID`); сущности; поддеревья `svg`/`math`.
* **Таблицы имён:** совершенный хэш для тегов и атрибутов, генерируемый при сборке.
* **DOM Builder:** дерево `DOM_NODE`, void-элементы, неявное закрытие тегов, лимиты (глубина 512 и др.), восстановление после любых ошибок разметки, без рекурсии.
* **Фаззинг токенизатора** с первого дня: мутационный фаззер на Python поверх `--dump-dom`.
* Режимы `--dump-dom <file> [--chunk N]` и `--bench parse <file>`.
  * *Критерий приемки:* golden-тесты на корпусе реальных страниц из `tests/pages/`; **дамп не зависит от разбиения входа на порции** (`--chunk` от 1 байта до целого файла, в том числе на страницах в UTF-8 с кириллицей и в windows-1251); фаззер не находит падений за 1 час; **скорость HTML → DOM ≥ 200 МБ/с** на корпусе `tests/bench/`.

## Milestone 2: Режим чтения
* **Таблица ролей** тегов (`ARCHITECTURE.md`, раздел 6).
* **Visibility:** записи `STYLESHEET`, минимальный разбор CSS (`<style>`, `style=""`) — `display`/`visibility`, скрывающие и показывающие правила, составные селекторы, `@media` по ширине, `!important`, упрощённый каскад с порядком по источникам, игнорирование скрывающих правил для `html`/`body`; атрибуты `hidden`, `aria-hidden`; корзины правил. Фаззинг разбора CSS.
* **Измерение текста** через `SysFont` (GDI работает и без окна, через memory DC): `GetCharABCWidthsW` для символов шрифта, `GetTextExtentPoint32W` для подставленных (проверка через `GetGlyphIndicesW`), кэш ширин.
* **Тестовый шрифт** (`--font-mock`): фиксированные метрики символов, чтобы эталоны раскладки совпадали под Wine и на любой Windows.
* **Reader Layout:** нормализованный текст (`text`), колонка, абзацы, заголовки, списки (`start`, `reversed`), цитаты, `pre`, таблицы построчно, `details`, `hr`, строчное оформление, перенос строк и принудительный разрыв длинных слов → массив `LINE` + `FRAGMENT`, `DOM_NODE.Line_Index`. Без рекурсии.
* **Картинки (раскладка):** запись `IMAGE`, выбор источника (`src`/`data-src`/`srcset`), пропуск скрытых и трекинг-пикселей, место по `width`/`height` или рамка с `alt`.
* Режимы `--dump-vis`, `--dump-layout <file> [--width N] [--font-mock]`, `--bench vis|layout`.
  * *Критерий приемки:* golden-тесты раскладки с тестовым шрифтом; на корпусе реальных страниц основной текст виден, а типовые скрытые элементы (мобильные меню, cookie-баннеры, модальные окна) — нет; проверяется списками ожидаемо видимых и скрытых элементов для каждой страницы при ширине 1280 и 400 px.

## Milestone 3: Окно и отрисовка
* **SysGUI:** окно, DIB-буфер, Per-Monitor V2 DPI (`WM_DPICHANGED`), светлая/тёмная тема из реестра, цикл сообщений.
* **Painter:** текст с `lpDx`, ссылки, маркеры, полосы цитат, линии; двоичный поиск видимых строк.
* **SysImage:** WIC — размер из заголовка, декодирование с уменьшением, лимиты мегапикселей, кэш пикселей 6 МБ × масштаб² с вытеснением, альфа-смешивание SSE2. Локальные картинки рядом с HTML-файлом. Фаззинг испорченными файлами картинок.
* **Прокрутка:** колесо мыши, клавиши, полоса прокрутки. **Resize** и смена DPI — перекладка с сохранением якоря прокрутки.
* **Выделение текста** мышью, `Ctrl+A`, `Ctrl+C`; масштаб `Ctrl+±`.
* Открытие локального файла: `nanoweb.exe page.html`; режим `--stats`.
  * *Критерий приемки:* корпус страниц отображается корректно (скриншоты сверены вручную, затем фиксируются как эталоны); Private Bytes < 6 МБ без страницы (окно 1280×800); прокрутка 60 FPS; при переносе окна на монитор с другим масштабом текст остаётся чётким.

## Milestone 4: Сеть (WinHTTP)
* **URL:** разбор, относительные ссылки, `<base href>`, `file://`, IDN (`IdnToAscii`), percent-encoding.
* **SysNet:** асинхронный WinHTTP; пулы `FETCH` (48) и `DOC_CTX` (4) с очередями ожидания; колбэк пишет только свои поля слота и вызывает `PostMessageW` с номером выдачи слота (`Seq`) в `lParam`; таймер загрузки только пока идёт загрузка; выход через `TerminateProcess`; «подметание» пула по таймеру; чтение блоками 8→64 КБ через `arena_ensure`; протокол отмены через `HANDLE_CLOSING`; Esc без освобождения памяти текущей страницы (`ARCHITECTURE.md`, раздел 5.2).
* HTTPS, HTTP/2, распаковка gzip, редиректы, cookies сессии, системный прокси, таймауты; заголовки как у Chrome, `Accept-Language` из системы, `Referer`.
* **Потоковый разбор** и показ страницы по мере загрузки; перезапуск разбора при позднем `<meta charset>`.
* **Ресурсы:** внешние таблицы стилей и `@import` (лимиты из раздела 7 архитектуры), картинки (до 6 загрузок, видимые первыми, арены с шагом 4 КБ).
* **Ответы и ошибки** по таблице из раздела 5.3 архитектуры: `text/plain`, картинка по прямой ссылке, неподдерживаемые типы → внешняя программа, `meta refresh`, ошибки сети, сертификата, редирект на http.
* Esc — остановка загрузки; ход загрузки в строке состояния.
  * *Критерий приемки:* открываются http- и https-сайты из тестового набора; badssl.com (просроченный и самоподписанный сертификаты) даёт предупреждение; набор тестов против локального сервера (медленная отдача, обрыв, большие и битые картинки, windows-1251 без `charset` в заголовке) проходит; навигация во время загрузки не приводит к сбоям (стресс-тест: 100 быстрых переходов подряд); интерфейс не замирает; Private Bytes < 20 МБ на тестовом наборе с картинками.
  * *Проверка риска:* выдача DuckDuckGo Lite открывается без капчи. Если капча появляется регулярно — простые формы переносятся в MVP (`ARCHITECTURE.md`, раздел 10.1).

## Milestone 5: Навигация и поиск (завершение MVP)
* Адресная строка (`EDIT` с подклассом для Enter/Esc), строка состояния.
* Ссылки: клик, курсор-рука, адрес в строке состояния; `Ctrl+клик` / средняя кнопка — новое окно; контекстное меню «Открыть в новом окне», «Копировать адрес»; якоря `#id`.
* История: Назад/Вперёд (`Alt+←`/`Alt+→`, `Backspace`, X1/X2) с кэшем текста страниц 4 МБ и восстановлением позиции; обновление (`F5`). Заголовок окна из `<title>`.
* **Поиск из адресной строки:** шаблоны и префиксы из `nanoweb.ini` (DuckDuckGo Lite, `w` — Википедия); распознавание антибот-страниц и предложение другого поисковика.
* **Поиск по странице (Ctrl+F):** SIMD-поиск по буферу `text`, без учёта регистра (латиница и кириллица), подсветка, F3 / Shift+F3. Режим `--bench find`.
  * *Критерий приемки:* по тестовому набору сайтов можно перемещаться по ссылкам и назад, «Назад» с кэшем возвращает на ту же позицию без загрузки из сети; запрос из адресной строки открывает выдачу поисковика; Ctrl+F на странице 1 МБ < 5 мс; все KPI из `ARCHITECTURE.md` (раздел 14) выполнены и зафиксированы в отчёте.

## После MVP (порядок предварительный)

### M6: Формы
* `<input>`, `<textarea>`, `<select>`, `<button>`; отправка `GET`/`POST` через WinHTTP — вход на форумы, поиск на сайтах без JS.

* Настоящая сетка для таблиц с данными, анимация GIF, переключатель «скрыть навигацию» (`nav`, `aside`, `footer`), User-Agent по доменам, клавиатурная навигация по ссылкам (Tab/Enter).
