# ДОКУМЕНТ ОПИСАНИЯ АРХИТЕКТУРЫ (SAD - Software Architecture Document)
**Проект:** Сверхлегкий веб-браузер (NanoWeb)
**Платформа:** Windows 10/11 x64
**Язык:** Ассемблер x86-64 (FASM)

## 1. Архитектурная парадигма
NanoWeb — **браузер для чтения**: он показывает содержимое страниц в едином аккуратном оформлении (режим чтения), а не воспроизводит дизайн сайтов. Цель — качественный сёрфинг по сайтам с содержимым и максимально быстрый разбор страниц.

Браузер проектируется по паттерну **Event-Driven Single-Process Architecture (событийно-ориентированная однопроцессная архитектура)**. Вся логика работает в главном потоке; события сети и окна приходят в **один** цикл сообщений Windows, поэтому загрузка не блокирует интерфейс.

Ключевые принципы:
* **Собственный движок разбора и отображения.** HTML, режим чтения и отрисовка реализуются самостоятельно. Готовые браузерные движки (WebView2, MSHTML) не используются.
* **Без сторонних библиотек.** Только системные DLL Windows: `kernel32`, `user32`, `gdi32`, `advapi32` (тема из реестра), `shell32` (открытие неподдерживаемых файлов во внешней программе), `winhttp`, `ole32`, `windowscodecs`. C-runtime не используется.
* **Сеть и декодирование картинок — системные** (WinHTTP, WIC). Собственные силы тратятся на разбор и отображение.
* **Изоляция ОС.** Весь платформенно-зависимый код находится в слое HAL. Движок не вызывает WinAPI напрямую.
* **Безопасность по умолчанию.** Всё, что приходит из сети, — недоверенные данные; на ассемблере это требует явных лимитов и отказа от рекурсии (раздел 12).

## 2. Уровни системы (Layered Architecture)

### Уровень 1: HAL — Hardware Abstraction Layer (`src/hal/win64/`)
Обертки над WinAPI. Вызываются через таблицу импорта PE (прямые `syscall` в Windows не используются — номера системных вызовов меняются между сборками ОС).

| Модуль | WinAPI | Назначение |
|---|---|---|
| `SysMem` | `VirtualAlloc`, `VirtualFree` | Резервирование и фиксация памяти для арен |
| `SysNet` | `winhttp` (асинхронный режим) | HTTP/HTTPS-загрузка (раздел 5) |
| `SysGUI` | `user32`: окно, цикл сообщений, `EDIT`, меню, буфер обмена; `gdi32`: `CreateDIBSection`, `BitBlt` | Окно, кадровый буфер, ввод, буфер обмена |
| `SysFont` | `gdi32`: `CreateFontW`, `GetGlyphIndicesW`, `GetCharABCWidthsW`, `GetTextExtentPoint32W`, `ExtTextOutW` | Измерение и вывод текста (раздел 8.1) |
| `SysImage` | `ole32`: `CoInitializeEx`, `CoCreateInstance`; WIC (`windowscodecs`) | Размер и декодирование картинок с уменьшением (раздел 8.2) |
| `SysFile` | `CreateFileW`, `ReadFile`, `WriteFile`, `GetStdHandle` | Локальные файлы, настройки, отладочный вывод |
| `SysOs` | `RegGetValueW` (advapi32), `ShellExecuteW` (shell32), `IdnToAscii`, `GetUserDefaultLocaleName`, `K32GetProcessMemoryInfo`, `QueryPerformanceCounter` | Тема, внешние программы, IDN, язык системы, статистика |

WinHTTP-сессия и WIC-фабрика создаются **лениво** — при первой навигации и первой картинке, а не при старте.

### Уровень 2: Core Services (`src/core/`)
* **Memory Allocator** — арены поверх `SysMem` (см. `MEMORY_MODEL.md`).
* **Event Loop** — главный цикл сообщений (раздел 4).
* **URL** — разбор, разрешение относительных ссылок и `<base href>`, IDN (`IdnToAscii`), percent-encoding не-ASCII символов пути и запроса, шаблоны поиска.
* **Encoding** — определение кодировки и перекодирование в UTF-8.
* **Settings** — чтение `nanoweb.ini`.
* **History** — история и кэш «Назад/Вперёд».

### Уровень 3: Web Engine (`src/engine/`)
* **HTML Tokenizer** — быстрый возобновляемый конечный автомат (разделы 6 и 11).
* **DOM Builder** — строит дерево `DOM_NODE`, применяя правила неявного закрытия тегов.
* **Visibility** — минимальный разбор CSS сайта: только правила, влияющие на видимость элементов (раздел 7).
* **Reader Layout** — раскладка в режиме чтения: нормализованный текст, одна колонка, собственные стили по роли элемента, перенос строк. Результат — плоский **массив строк** (раздел 8).

### Уровень 4: Presentation (`src/paint/`, `src/ui/`)
* **Painter** — рисует видимые строки в кадровый буфер.
* **UI** — адресная строка, строка состояния, прокрутка, ссылки, выделение и копирование, история, поиск (разделы 9 и 10).

## 3. Поток данных (Data Flow)
1. **Input:** пользователь вводит URL или запрос, кликает по ссылке → создаётся новый `DOC_CTX`, предыдущий переходит в закрытие (раздел 5.2).
2. **Fetch:** `SysNet` асинхронно загружает страницу через WinHTTP. Для `file://` и пути в командной строке данные читаются через `SysFile`.
3. **Decode:** документ всегда принимается в арену `raw`. Кодировка определяется в порядке BOM → `charset` из `Content-Type` → `<meta charset>` в первых 1024 байтах (предварительный просмотр до разбора). По мере прихода данные переносятся из `raw` в `src`: UTF-8 копируется с заменой невалидных последовательностей на U+FFFD, другие кодировки перекодируются. Если `<meta charset>` найден позже и отличается — `src` и `doc` сбрасываются, разбор начинается заново из `raw`. После окончания загрузки `raw` освобождается.
4. **Parse:** `HTML Tokenizer` → `DOM Builder` строят дерево в `doc` по мере прихода данных. Содержимое `<style>`, `style=""` и внешних таблиц стилей передаётся в `Visibility`.
5. **Visibility:** элементы получают `NF_HIDDEN` по правилам видимости для текущей ширины окна.
6. **Images:** для видимых `<img>` создаются записи `IMAGE`; загрузка — параллельно, видимые на экране первыми (раздел 8.2). Картинки скрытых элементов не загружаются.
7. **Layout:** строятся нормализованный текст (`text`), фрагменты (`layout`) и массив строк (`line`).
8. **Paint:** `Painter` двоичным поиском находит первую видимую строку и рисует видимую часть в DIB-буфер.
9. **Display:** `BitBlt` выводит буфер в окно.

**Показ по мере загрузки.** Страница показывается, как только разобраны первые 16 КБ или прошло 200 мс с начала ответа; во время загрузки раскладка обновляется не чаще раза в 250 мс с сохранением якоря прокрутки. Сроки отслеживаются одним таймером окна (`WM_TIMER`, 50 мс) по полям `DOC_CTX.Started_At` / `Last_Layout_At`.

| Событие | Этапы |
|---|---|
| Навигация | 1 → 9 полностью |
| Изменение ширины окна | 5 (условия `@media`) → 7 → 9, с сохранением якоря прокрутки |
| Смена DPI (`WM_DPICHANGED`), масштаб `Ctrl+±` | Пересоздание шрифтов, 7 → 9 |
| Пришла таблица стилей | 5 → 7 → 9 |
| Стал известен размер картинки | 7 → 9 |
| Прокрутка | Только 8 → 9 (+ декодирование картинок, попавших в видимую область) |
| Клик / наведение | Двоичный поиск строки по Y, затем фрагмента по X |

**Якорь прокрутки:** перед перекладкой запоминается `LINE.Node` верхней видимой строки и смещение внутри неё; после — по `DOM_NODE.Line_Index` этого узла восстанавливается позиция. Так текст под глазами не «прыгает».

## 4. Event Loop и отрисовка
* Цикл: `GetMessageW` → `TranslateMessage` → `DispatchMessageW`. Оконная процедура обрабатывает `WM_SIZE`, `WM_PAINT`, `WM_DPICHANGED`, `WM_MOUSEWHEEL`, `WM_KEYDOWN`, `WM_LBUTTONDOWN/UP`, `WM_MOUSEMOVE`, `WM_CONTEXTMENU`, `WM_SETTINGCHANGE` (смена темы, `lParam = "ImmersiveColorSet"`), `WM_TIMER` (сроки показа и перекладки при загрузке, ожидание таблиц стилей, таймауты «тихих» соединений, «подметание» пула `FETCH`) и `WM_NET` (`WM_APP+1`, события WinHTTP — раздел 5).
* **Перерисовка только по необходимости** (dirty flag + `InvalidateRect`): в покое браузер не потребляет CPU.
* **Двойная буферизация:** DIB-секция служит задним буфером. Цель — 60 FPS при прокрутке.
* **DPI — Per-Monitor V2**, объявляется в манифесте приложения (встроенный ресурс). По `WM_DPICHANGED` окно принимает предложенный размер, шрифты пересоздаются (включая шрифт `EDIT`-контрола адресной строки: новый `WM_SETFONT` и пересчёт его высоты — comctl32 этого сам не делает), страница перекладывается. Тот же манифест включает визуальные стили (`comctl32` v6) для `EDIT`-контрола адресной строки.
* **Темы:** светлая и тёмная, по значению `AppsUseLightTheme` в реестре; смена — по `WM_SETTINGCHANGE`.

### Painter
* Фон, линии `<hr>`, полосы цитат, подчёркивания, выделение — собственным кодом (`rep stosd` / SSE2) прямо в пиксели DIB.
* Текст — через GDI (`ExtTextOutW`) в контекст той же DIB-секции, **поверх уже залитого фона** (`SetBkMode(TRANSPARENT)`), иначе сглаживание ClearType посчитается относительно мусора. Перед прямой записью пикселей после вызовов GDI обязателен `GdiFlush`. ClearType обнуляет альфа-канал пикселей текста — для `BitBlt` это неважно, альфа-смешивание кадра целиком не используется.
* В `ExtTextOutW` передаётся массив `lpDx` (по элементу на каждый `WCHAR`; у второй половины суррогатной пары — 0) из тех же ширин символов, по которым считалась раскладка: отрисовка точно совпадает с измерением, и подсветка Ctrl+F, выделение и клики не «плывут».
* Картинки — собственное альфа-смешивание SSE2.

## 5. Сеть: WinHTTP

### 5.1. Запрос
WinHTTP работает в асинхронном режиме (`WINHTTP_FLAG_ASYNC`); колбэк устанавливается один раз на сессию с подпиской только на нужные события (`WINHTTP_CALLBACK_FLAG_ALL_COMPLETIONS | REDIRECT | SECURE_FAILURE | HANDLE_CLOSING`), чтобы не получать десяток информационных сообщений на каждый запрос. Колбэк вызывается в служебных потоках WinHTTP, может вызываться повторно и параллельно. Поэтому он пишет **только** поля `Bytes_Read`, `Win_Error`, `Secure_Flags` своего слота `FETCH` (а при `HANDLE_CLOSING` — `State = Закрыт`) и вызывает `PostMessageW(hwnd, WM_NET, индекс_слота, статус | (Generation << 32))`; вызовы с `dwContext = 0` игнорирует (`MEMORY_MODEL.md`, раздел 8). Вся обработка — в главном потоке.

Цепочка: `WinHttpConnect` → `WinHttpOpenRequest` → `WinHttpSendRequest` → `WinHttpReceiveResponse` → `WinHttpQueryHeaders` (статус, `Content-Type`, `Content-Length`) → цикл `WinHttpReadData`:
* `WinHttpQueryDataAvailable` не используется — данные читаются сразу блоками. Размер блока (`FETCH.Read_Block`) начинается с 8 КБ и удваивается после каждого полностью заполненного блока до 64 КБ: мелкие ресурсы не занимают лишнюю память, крупные читаются за малое число вызовов;
* перед каждым `WinHttpReadData` вызывается `arena_ensure(Target, Read_Block)`, буфер передаётся указателем на `Target.Ptr`; `lpdwNumberOfBytesRead = NULL`;
* по `READ_COMPLETE` главный поток делает `arena_advance(Bytes_Read)`, передаёт новые данные разборщику и запускает следующее чтение; `Bytes_Read = 0` — конец ответа;
* `Content-Length` используется только для строки состояния: при распаковке он описывает сжатое тело. Лимиты размера считаются по реально принятым байтам.

Настройки сессии:
* HTTPS и проверка сертификатов; HTTP/2 (`WINHTTP_OPTION_ENABLE_HTTP_PROTOCOL`, Windows 10 1607+; ошибка опции на старых версиях игнорируется);
* распаковка gzip/deflate (`WINHTTP_OPTION_DECOMPRESSION`, Windows 8.1+); заголовок `Accept-Encoding` выставляет сам WinHTTP — brotli он не поддерживает, вручную `br` не добавляется;
* автоматические редиректы (по умолчанию WinHTTP запрещает редирект с https на http — тогда показывается страница с предупреждением и ссылкой);
* cookies — хранилище сессии WinHTTP, в памяти до закрытия браузера;
* системный прокси (`WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY`, Windows 8.1+); статус `GETPROXYFORURL_COMPLETE` обрабатывается;
* таймауты (`WinHttpSetTimeouts`): соединение 15 с, ответ 30 с; дополнительно по таймеру окна — 60 с без новых данных («тихое» соединение) для запроса, который уже начал приём.

Заголовки запроса:
* `User-Agent` — **как у Chrome под Windows** (строка в `nanoweb.ini`, обновляется вместе с версиями Chrome): сайты реже показывают антибот-страницы. Минус: некоторые сайты отдают «Chrome» более тяжёлую JS-версию — для таких после MVP можно будет задать отдельный User-Agent по домену.
* `Accept: text/html,...`, `Accept-Language` из языка системы (`GetUserDefaultLocaleName`, например `ru-RU,ru;q=0.9,en;q=0.8`), `Referer` — адрес страницы, с которой пришли (не отправляется при переходе с https на http и при открытии ссылки в новом окне).

### 5.2. Отмена и смена документа
`WinHttpCloseHandle` в асинхронном режиме завершается **асинхронно**: пока не пришло `HANDLE_CLOSING`, WinHTTP может дописать данные в переданный буфер. Поэтому:
1. При навигации номер поколения (`Generation`) увеличивается; для всех активных `FETCH` старого документа вызывается `WinHttpCloseHandle`, их состояние — «Закрывается».
2. Старый `DOC_CTX` получает состояние «Закрывается»; новый документ загружается в другой слот пула (4 слота). Если свободного нет — навигация ждёт ближайшего освобождения.
3. Сообщения `WM_NET`, у которых поколение в `lParam` не совпадает с поколением слота, игнорируются. `HANDLE_CLOSING` — всегда последний колбэк хэндла, а очередь сообщений упорядочена, поэтому все устаревшие сообщения слота обрабатываются раньше, чем слот освободится и будет использован снова.
4. Слот `FETCH` в состоянии «Закрыт» освобождается — по сообщению `HANDLE_CLOSING` или при «подметании» пула (на каждом `WM_NET` и по таймеру раз в секунду: на случай, если `PostMessageW` не смог поставить сообщение в переполненную очередь). При освобождении уменьшается `In_Flight` его документа.
5. Когда `In_Flight` документа в состоянии **«Закрывается»** достиг нуля — его арены и арены его ресурсов освобождаются.

Esc (кнопка «Стоп») закрывает запросы текущего документа, но не переводит его в «Закрывается»: загрузка прекращается, полученная часть страницы остаётся на экране, арены сохраняются.

При выходе из программы вызывается `WinHttpCloseHandle` для сессии и сразу `ExitProcess` без ожидания `HANDLE_CLOSING`: пулы статические, поэтому поздние колбэки не обращаются к освобождённой памяти.

### 5.3. Ответы и ошибки
| Ситуация | Поведение |
|---|---|
| `text/html`, `application/xhtml+xml` | Обычный разбор |
| `text/plain` | Показ моноширинным шрифтом с переносом строк |
| `image/*` по прямой ссылке | Страница из одной картинки |
| Другие типы (PDF, архивы…) | Встроенная страница «Этот тип файлов не поддерживается» с кнопкой «Открыть во внешней программе» (`ShellExecuteW` с URL — откроет системный браузер или загрузчик) |
| `<meta http-equiv="refresh">` | С задержкой ≤ 10 с — переход; иначе ссылка вверху страницы |
| Документ больше 32 МБ | Показывается первая часть и сообщение об обрезке |
| Ошибка DNS, соединения, таймаут | Встроенная страница ошибки с кнопкой «Повторить» |
| HTTP 4xx/5xx | Показывается тело ответа сайта (обычно это его страница ошибки) |
| Ошибка сертификата (`SECURE_FAILURE`) | Страница предупреждения с причиной; «Продолжить всё равно» — новый запрос с `WINHTTP_OPTION_SECURITY_FLAGS` (`SECURITY_FLAG_IGNORE_*`) |

Во встроенных страницах любые данные от сайта (URL, текст ошибки) экранируются как HTML.

## 6. Поддерживаемый HTML
* Теги, атрибуты (в кавычках и без), комментарии; `<!DOCTYPE>` отбрасывается; void-элементы.
* Неявное закрытие `<p>`, `<li>`, `<td>`, `<tr>`, `<option>`, `<dt>`, `<dd>`.
* Raw text: содержимое `<script>` пропускается, `<style>` передаётся в Visibility, `<textarea>`/`<title>` — текст без разметки.
* Поддерево `<svg>` и `<math>` пропускается целиком (включая вложенные `<title>`/`<text>`); у `<math>` показывается атрибут `alttext`, если есть.
* `<noscript>` **показывается** — JavaScript у нас нет, и сайты кладут туда версию для таких браузеров.
* `<base href>` учитывается при разрешении ссылок.
* Сущности: числовые (значения вне Unicode и суррогаты → U+FFFD) и основные именованные (`amp lt gt quot apos nbsp copy reg trade mdash ndash laquo raquo hellip bull middot times deg`…).
* Кодировки: UTF-8, windows-1251, windows-1252 / ISO-8859-1, KOI8-R (таблицы по 128 символов).
* Восстановление после любых ошибок разметки: на любом входе программа не падает и что-то показывает.

### Роли элементов в режиме чтения
Каждому тегу по статической таблице назначается роль; оформление роли задано в браузере, CSS сайта на него не влияет.

| Роль | Теги | Оформление |
|---|---|---|
| Абзац | `p`, `div`, `section`, `article`, `main`, `header`, `footer`, `nav`, `aside`, `figure`, `figcaption`, `form`, `address`, `center`, `fieldset`, `legend` | Блок, отступ между абзацами |
| Заголовок | `h1`–`h6` | Крупнее и жирнее по уровню |
| Список | `ul`, `ol` (с `start`, `reversed`), `dl`; `li`, `dt`, `dd` | Отступ по уровню вложенности, маркер `•` или номер |
| Цитата | `blockquote` | Отступ и вертикальная полоса слева |
| Преформатированный | `pre` | Моноширинный шрифт, длинные строки переносятся с меткой `↩` |
| Таблица | `table`, `caption`, `thead`, `tbody`, `tfoot`, `tr`, `td`, `th` | В MVP каждая строка таблицы — одна строка текста, ячейки через `│`; `caption` — абзац над таблицей |
| Раскрывающийся блок | `details`, `summary` | Без атрибута `open` показывается только `summary` с маркером `▸`; клик раскрывает |
| Линия | `hr` | Горизонтальная линия |
| Строчные | `a`, `b`, `strong`, `i`, `em`, `code`, `kbd`, `samp`, `var`, `u`, `s`, `del`, `ins`, `sub`, `sup`, `span`, `small`, `mark`, `abbr`, `q`, `cite`, `time`, `label`, `font` | Ссылка, жирный, курсив, моноширинный, подчёркнутый, зачёркнутый или без изменений |
| Перевод строки | `br` | — |
| Картинка | `img` | Раздел 8.2 |
| Заменитель | `iframe`, `video`, `audio`, `embed`, `object` | Ссылка на источник, приглушённым цветом |
| Не показывается | `head`, `script`, `style`, `template`, `canvas`, `select`, `input`, `textarea`, `button`, `dialog` (без `open`) | — |

Незнакомые теги ведут себя как строчные. Шрифты: основной (Segoe UI) и моноширинный (Consolas); символы, которых в них нет (CJK, арабский и др.), GDI подставляет из других шрифтов автоматически (font linking).

## 7. Видимость элементов (Visibility)
Режим чтения игнорирует CSS сайта, кроме видимости: сайты прячут через CSS мобильные меню, всплывающие окна, cookie-баннеры. При этом многие сайты «мобильные в первую очередь»: элемент скрыт по умолчанию и **показывается** правилом `@media (min-width: …)` или более специфичным селектором. Поэтому учитываются и скрывающие, и показывающие правила.

**Источники:**
* атрибуты `hidden` и `aria-hidden="true"` — элемент скрыт всегда (`NF_HIDDEN_ATTR`), кроме `aria-hidden` на `html`, `body` и `main` (сайты так «замораживают» страницу под открытым модальным окном);
* `style=""` элемента — `display` и `visibility`;
* `<style>`, внешние таблицы стилей (`<link rel="stylesheet">`, кроме `media="print"`) и `@import` из них.

**Разбор CSS — минимальный:**
* из объявлений нужны только `display` и `visibility` (с `!important`); остальные пропускаются без разбора значений;
* `display: none` или `visibility: hidden` → правило «скрыть»; любое другое значение `display` или `visibility: visible` → правило «показать»;
* селекторы: `*`, тег, `.class`, `#id`, их сочетания (`div.a.b#c`), потомок (пробел), ребёнок (`>`), список через запятую. Правило с непонятным селектором (атрибуты, псевдоклассы, `+`, `~`) пропускается целиком — лучше показать лишнее, чем спрятать нужное;
* `@media`: учитываются типы `screen`/`all` и условия `min-width`/`max-width` в `px` и `em` (сравниваются с текущей шириной окна в CSS px и пересчитываются при её изменении); `print` и прочие условия — блок пропускается.

**Решение для элемента** — упрощённый каскад: среди подходящих правил побеждает `!important`, затем большая специфичность, затем более поздний порядок; объявление в `style=""` сильнее правил без `!important`. Если победило «скрыть» — элемент и всё его поддерево не показываются. **Скрывающие правила для `html` и `body` игнорируются**: сайты прячут так всю страницу до запуска JavaScript, который у нас не выполнится. `visibility: hidden` упрощённо трактуется как `display: none` (переопределение `visibility: visible` у потомка не поддерживается).

**Лимиты загрузки:** не больше 8 таблиц стилей на страницу, не больше 512 КБ каждая. Раскладка ждёт таблицы стилей не дольше 300 мс, затем показывает страницу и перекладывает её по приходу.

## 8. Режим чтения (Reader Layout)

### 8.1. Текст и строки
* Один **итеративный** проход по DOM в порядке документа (явный стек в `scratch`, без рекурсии). Строчное оформление (жирный, курсив, ссылка, моноширинный) — счётчики вложенности, а не вычисленный стиль на каждый элемент.
* Видимый текст копируется в буфер `text` с нормализацией: пробелы и переводы строк схлопываются (кроме `pre`), между блоками — разделитель. Буфер — основа для фрагментов, Ctrl+F, выделения и копирования.
* Текст режется на слова и раскладывается по строкам шириной колонки (около 70 символов, по центру окна; ширина и размер шрифта — в `nanoweb.ini` и `Ctrl+±`). Слово длиннее строки (URL, текст без пробелов, CJK) **принудительно разрывается** по символам.
* Ширины символов измеряются через `SysFont` с кэшем на шрифт; кернинг не учитывается — ни при измерении, ни при отрисовке (через `lpDx`).
  * Символы, которые есть в выбранном шрифте (проверка через `GetGlyphIndicesW` с `GGI_MARK_NONEXISTING_GLYPHS`), измеряются `GetCharABCWidthsW` — быстро и сразу диапазонами.
  * Символы, которых в шрифте нет (CJK, арабский и др.), GDI рисует из подставленного шрифта (font linking), а `GetCharABCWidthsW` вернул бы ширину не того глифа. Их ширина измеряется `GetTextExtentPoint32W` (учитывает подстановку) по одному символу и кэшируется по кодовой точке.
* Результат — **плоский массив строк** (`LINE`) сверху вниз и фрагменты (`FRAGMENT`). Дерева блоков нет: маркер списка, полоса цитаты, линия `hr` привязаны к строкам. Отрисовка видимой части и поиск строки под курсором — двоичный поиск за `O(log n)`; прокрутка не требует пересчёта.
* Во время раскладки каждому отображаемому элементу записывается `DOM_NODE.Line_Index` — для якорей `#id` и сохранения позиции прокрутки.
* В конце буферов `src` и `text` всегда есть ≥ 32 байта зафиксированной памяти (`arena_ensure`) — для SIMD-чтения без проверки конца.
* **Ограничения MVP:** письмо справа налево (арабский, иврит) отображается без переупорядочивания; цветные emoji GDI рисует одноцветными.

### 8.2. Картинки
Картинки показываются автоматически (отключается в `nanoweb.ini`: `[images] enabled = 0`).
* **Выбор источника.** Берётся `src`; если в `src` заглушка (`data:`-картинка или пустой GIF), а есть `data-src` / `data-original` / `data-lazy-src` — берётся он: без JS скрипты «ленивой загрузки» не сработают. Из `srcset` выбирается вариант, ближайший к ширине колонки × DPI. `data:` URI (до 1 МБ) декодируются из base64 в арену ресурса картинки.
* **Пропуск:** картинки внутри скрытых элементов не загружаются; картинки с атрибутами `width` и `height` не больше 2 px (трекинг-пиксели) — тоже. Если размер выяснился только из заголовка файла и он не больше 2×2 px — картинка не показывается.
* **Загрузка.** Через WinHTTP, до 6 одновременно; первыми — картинки в видимой области (по `Line_Index`, до первой раскладки — в порядке документа). Каждая картинка — в собственную арену ресурса. Файлы больше 16 МБ не загружаются.
* **Размер до декодирования.** Если у `<img>` есть `width`/`height` — место резервируется сразу. Иначе размер читается из заголовка файла (`IWICBitmapFrameDecode::GetSize` с `WICDecodeMetadataCacheOnDemand`, без распаковки) сразу после загрузки, и страница перекладывается с сохранением якоря прокрутки.
* **Отображение:** блоком по ширине колонки (не шире оригинала); картинки уже 64 px — в строке текста (иконки). До загрузки и при ошибке — рамка с текстом `alt`.
* **Декодирование** — только для картинок в видимой области и рядом с ней. Поток из памяти: `IWICImagingFactory::CreateStream` + `IWICStream::InitializeFromMemory` (байты в арене ресурса живут дольше потока). Цепочка: декодер → `IWICBitmapScaler` до отображаемого размера → `IWICFormatConverter` в 32bpp PBGRA → `CopyPixels` в собственный буфер.
  * Для JPEG WIC уменьшает картинку **при декодировании** (DCT-масштабирование), поэтому даже огромная фотография не разворачивается в памяти целиком.
  * Для PNG, GIF, BMP, WebP такого пути нет: WIC временно распаковывает картинку полностью. Поэтому лимит: не больше 20 мегапикселей для этих форматов и 100 мегапикселей для JPEG; больше — показывается рамка с `alt` и ссылкой на файл.
* **Кэш пикселей** — 6 МБ × (масштаб DPI)², видимые картинки не вытесняются (`MEMORY_MODEL.md`, раздел 1.5).
* **Форматы:** JPEG, PNG, GIF (первый кадр), BMP, ICO; WebP и AVIF — если установлены соответствующие расширения из Microsoft Store (на Windows 11 WebP обычно предустановлен). SVG не поддерживается — показывается `alt`.
* Все объекты WIC используются только в главном потоке (`CoInitializeEx` с `COINIT_APARTMENTTHREADED`).

## 9. Интерфейс
* **Адресная строка** — стандартный `EDIT`-контрол; Enter и Esc перехватываются подклассом (`SetWindowLongPtrW(GWLP_WNDPROC)`).
* **Строка состояния:** адрес ссылки под курсором, ход загрузки (принято байт, картинки N из M).
* **Навигация:** клик по ссылке; `Ctrl+клик` или средняя кнопка — открыть в новом окне (новый процесс `nanoweb.exe <url>`: изоляция и простота; у каждого окна свои cookies — вход на сайт в одном окне не виден в другом); правый клик по ссылке — меню «Открыть в новом окне», «Копировать адрес»; переход к якорю `#id`.
* **История:** Назад/Вперёд (`Alt+←`/`Alt+→`, `Backspace`, кнопки мыши X1/X2) с кэшем текста страниц (`MEMORY_MODEL.md`, раздел 11), обновление (`F5`), Стоп (`Esc`). Заголовок окна из `<title>`.
* **Выделение текста** мышью, `Ctrl+A`, `Ctrl+C` → буфер обмена (`CF_UNICODETEXT`). Границы выделения хранятся как пара (`DOM_NODE.Order` текстового узла, смещение в нём), поэтому выделение переживает перекладку; при отрисовке пересчитываются в смещения буфера `text`.
* **Масштаб:** `Ctrl+±`, `Ctrl+0`, `Ctrl+колесо`.
* **Прокрутка:** колесо, клавиши (стрелки, PgUp/PgDn, Home/End, пробел), полоса прокрутки.
* **Настройки** — `nanoweb.ini`: рядом с `nanoweb.exe` (переносной режим), иначе `%APPDATA%\NanoWeb\nanoweb.ini`.

## 10. Поиск

### 10.1. Поиск из адресной строки
Ввод без схемы (`://`) и без точки считается запросом и подставляется в шаблон (`%s` — запрос в URL-кодировке UTF-8). Шаблоны и префиксы — в `nanoweb.ini`:

```ini
[search]
default = https://lite.duckduckgo.com/lite/?q=%s
w = https://ru.wikipedia.org/w/index.php?search=%s
```
Требование к поисковику — выдача обычным HTML без JavaScript. Google не подходит (требует JS с 2025 года).

**Антибот-защита (проверено 2026-10-01).** DuckDuckGo Lite отвечал простому HTTP-клиенту (curl) капчей с картинками; HTML-выдача Marginalia — промежуточной страницей «Wait a moment». Меры:
1. User-Agent и заголовки как у Chrome; TLS и HTTP/2 — стандартный сетевой стек Windows.
2. На этапе M4 проверяется, открывается ли DuckDuckGo Lite без капчи. Если капча появляется регулярно — простые формы переносятся в MVP (картинки в MVP уже есть).
3. Страница-заглушка (капча, «подождите») распознаётся, браузер предлагает другой поисковик из `nanoweb.ini`.

**После MVP — Marginalia через API** (префикс `m`, «Малый веб»): `GET https://api2.marginalia-search.com/search?query=…&count=20` с заголовком `API-Key` (ключ `public` работает без регистрации, проверено 2026-10-01), ответ JSON разбирается собственным минимальным парсером. Marginalia ищет текстовые сайты без JS, которые NanoWeb показывает полностью; минусы — индекс только на английском, проект поддерживает один человек, общий ключ при перегрузке отвечает `503`.

### 10.2. Поиск по странице (Ctrl+F)
* Поиск идёт по буферу `text`, поэтому находит совпадения и через границы фрагментов и строк; строка совпадения находится двоичным поиском по `LINE.Text_Start`.
* **SIMD-поиск подстроки:** первый и последний байт образца сравниваются сразу с 16 (SSE2) или 32 (AVX2) позициями; полное сравнение — только для кандидатов.
* Без учёта регистра для латиницы и кириллицы в UTF-8 (компактная таблица, без полного Unicode).
* Совпадения хранятся в арене `find`; подсветка обновляется на каждый символ; F3 / Shift+F3 — следующее и предыдущее совпадение. После перекладки поиск выполняется заново.

## 11. Производительность разбора
Скорость разбора — ключевое требование проекта:
* **SIMD-сканирование.** Токенизатор пропускает текст и значения атрибутов блоками по 16 байт (SSE2 — есть на любом x64-процессоре), ища только значимые символы (`<`, `&`, `\r`, `\0`, кавычку). Путь AVX2 (32 байта) включается после проверки `CPUID`.
* **Zero-copy.** Токены и текстовые узлы — срезы буфера `src`; копирование только при декодировании сущностей.
* **Bump-аллокация.** Создание узла — сдвиг указателя арены.
* **Идентификаторы вместо строк.** Имена тегов и атрибутов переводятся в числа через совершенную хэш-функцию, генерируемую на этапе сборки.
* **Автомат через таблицу переходов** (`jmp [table + state*8]`).
* **Потоковый разбор** по мере прихода данных; результат не зависит от того, как вход разбит на порции (проверяется тестами).
* **Правила видимости** раскладываются по корзинам по самой правой части селектора.
* **Замеры:** `nanoweb.exe --bench parse|vis|layout|find <file> [N]` печатает МБ/с и время этапов на корпусе `tests/bench/` (меряется обработка уже загруженного буфера). Регрессия скорости больше 5% считается ошибкой.

## 12. Безопасность
Разборщики недоверенных данных на ассемблере — главный источник рисков. Правила:

**Исполняемый файл:**
* `format PE64 NX GUI 6.0` (флаг `NX_COMPAT` — DEP) с секцией перемещений (`data fixups`). Директив для `DYNAMIC_BASE` и `HIGH_ENTROPY_VA` (ASLR) у FASM нет, поэтому после сборки их выставляет скрипт `tools/patch_pe.py` (поле `DllCharacteristics` = `0x0160`), а `tools/check_pe.py` в CI проверяет флаги и наличие перемещений. На этапе M0 стоит проверить и вариант без скрипта — запись поля директивой `store` из самого исходника.
* Размер стека задаётся явно: `stack 0x100000` (1 МБ).

**Код:**
* **Никакой рекурсии** при обходе DOM, сопоставлении селекторов и раскладке — только явные стеки ограниченного размера.
* Числа из входных данных разбираются с насыщением (`width="99999999999"` → верхний предел, а не переполнение); произведения размеров (`W × H × 4`) проверяются до выделения памяти.
* Любое чтение входного буфера проверяет границу среза; SIMD-чтение за концом данных допускается только внутри зафиксированной памяти арены (в конце буфера всегда ≥ 32 байта запаса).

**Лимиты:**
| Что | Предел | При превышении |
|---|---|---|
| Размер документа (после декодирования) | 32 МБ | Обрезка с сообщением |
| Глубина вложенности DOM | 512 | Глубже — узлы добавляются к элементу на глубине 512 (как в браузерах) |
| Узлов в документе | 2 000 000 | Остаток документа не разбирается |
| Атрибутов у элемента | 256 | Лишние отбрасываются |
| Таблиц стилей / размер каждой | 8 / 512 КБ | Пропуск |
| Правил видимости / частей селектора | 50 000 / 32 | Пропуск правила |
| Картинок на странице / размер файла | 1 000 / 16 МБ | Рамка с `alt` |
| Пиксели при декодировании | 20 Мп (JPEG — 100 Мп) | Рамка с `alt` и ссылкой |
| Отображаемый размер картинки | 16 384 px по стороне | Уменьшение |
| `data:` URI | 1 МБ | Рамка с `alt` |
| Редиректов подряд | 10 (ограничение WinHTTP) | Страница ошибки |

**Сбои:** фильтр необработанных исключений (`SetUnhandledExceptionFilter`) записывает в `%APPDATA%\NanoWeb\crash.log` код исключения, адрес, регистры и URL страницы (без выделения памяти и без COM) и показывает сообщение вместо тихого исчезновения окна. `AddVectoredExceptionHandler` не используется: он срабатывает и на исключения, которые системные DLL штатно обрабатывают сами.

**Тестирование:** фаззинг разборщиков начинается одновременно с ними (M1 — HTML, M2 — CSS, M3 — картинки через WIC с испорченными файлами).

## 13. Границы проекта
**Не цели (сознательно исключено):**
* Воспроизведение дизайна сайтов (CSS-вёрстка, цвета и шрифты сайтов).
* JavaScript. Сайты, которые без JS не показывают содержимое (веб-приложения, YouTube, большинство соцсетей), не поддерживаются.
* Аудио и видео.
* Плагины, расширения, синхронизация, WebGL, WebAssembly.

**Вне MVP:** печать; поддержка экранных дикторов (содержимое DIB-буфера им недоступно); письмо справа налево; цветные emoji; HTTP-кэш на диске; загрузка файлов; общие cookies между окнами.

**После MVP:** формы, Marginalia через API, закладки и подсказки адресов, вкладки, настоящая сетка для таблиц с данными, анимация GIF, переключатель «скрыть навигацию», User-Agent по доменам.

## 14. Метрики и KPI
Замеры памяти — при окне 1280×800 и масштабе 100%.

| Метрика | Цель | Как измеряется |
|---|---|---|
| Размер исполняемого файла | < 1 МБ | Размер `nanoweb.exe` |
| Скорость разбора HTML → DOM | ≥ 200 МБ/с на бенчмарк-корпусе | `--bench parse` |
| Последний байт страницы 1 МБ → первый кадр | < 20 мс | `--stats` |
| Ctrl+F на странице 1 МБ | < 5 мс | `--bench find` |
| Память без страницы | Private Bytes < 6 МБ, включая буфер кадра | `K32GetProcessMemoryInfo` (`PrivateUsage`) |
| Общее потребление | Private Bytes < 20 МБ на тестовом наборе страниц, включая картинки | `--stats`, Process Explorer |
| Прокрутка | 60 FPS | Время кадра в `--stats` |
| Простой | 0% CPU без событий | Process Explorer |

> Время запуска не является целевым показателем (решение владельца проекта). WinHTTP и WIC всё равно инициализируются лениво — ради памяти.
>
> Рабочий набор (Working Set) включает общие системные DLL, одинаковые для любого Win32-приложения, поэтому KPI по памяти заданы в Private Bytes.

## 15. Журнал решений
| # | Решение | Причина | Отклонённые варианты |
|---|---|---|---|
| 1 | Платформа — Windows 10/11 x64 | Выбор владельца проекта; ОС даёт окно, TrueType-шрифты, сетевой стек и декодеры картинок без сторонних библиотек | Linux (X11/Wayland вручную), MenuetOS 64 (возможен позже как ещё один HAL) |
| 2 | Ассемблер — FASM 1.73 | Нативная поддержка PE64, макросы `proc`/`invoke`/`struct`/COM, сборка без линкера | NASM (нужен внешний линкер) |
| 3 | Соглашение о вызовах — Microsoft x64 везде | Единообразие с WinAPI | Собственное внутреннее соглашение |
| 4 | Только собственный движок | Суть проекта — сверхлёгкий браузер | WebView2-оболочка, гибрид с WebView2 |
| 5 | Сеть через WinHTTP | HTTPS, HTTP/2, gzip, cookies, редиректы и прокси без собственной реализации. *Заменило решение «свой HTTP/1.1 + SChannel».* | Свой HTTP поверх Winsock + SChannel |
| 6 | Текст через GDI | TrueType, кириллица, сглаживание и подстановка шрифтов без своего растеризатора | Свой bitmap-шрифт, DirectWrite |
| 7 | Без JavaScript, аудио и видео | Цель — сёрфинг по сайтам с содержимым и скорость разбора | JS-движок, Media Foundation, YouTube через yt-dlp |
| 8 | Режим чтения вместо CSS-вёрстки; из CSS сайта — только видимость (скрывающие и показывающие правила, `@media` по ширине) | В разы меньше кода, одинаково читаемые страницы; учёт показывающих правил не прячет основной текст mobile-first сайтов | Полная CSS-вёрстка; только скрывающие правила (прячут текст навсегда); полный отказ от CSS (вылезают меню и окна) |
| 9 | Поиск: DuckDuckGo Lite по умолчанию, Википедия; Marginalia через API после MVP | Выдача без JS; DuckDuckGo покрывает русский язык; HTML Marginalia закрыт антибот-страницей, API работает | Google (требует JS), Marginalia в MVP |
| 10 | Картинки автоматически, в MVP, через WIC с уменьшением и кэшем 6 МБ × масштаб² | Выбор владельца проекта; уменьшение до колонки держит память в рамках KPI | Только `alt`; загрузка по клику |
| 11 | User-Agent как у Chrome под Windows | Выбор владельца проекта: реже антибот-страницы | Честный `NanoWeb/x` |
| 12 | DPI — Per-Monitor V2 через манифест | Выбор владельца проекта; перекладка дешёвая, окно не размывается на мониторах с разным масштабом | System DPI aware |
| 13 | Время запуска — не KPI | Выбор владельца проекта | «Холодный старт < 20 мс» |
| 14 | Пулы `FETCH` (48) и `DOC_CTX` (4), закрытие запросов до освобождения памяти, «подметание» слотов | Асинхронный WinHTTP может писать в буфер до `HANDLE_CLOSING`; колбэк должен куда-то сохранять данные, живущие только внутри вызова; `PostMessageW` может не доставить сообщение | Освобождение арен сразу после `WinHttpCloseHandle` |
| 15 | Документ всегда принимается в `raw` и переносится в `src` | Кодировка известна не сразу; перезапуск разбора при позднем `<meta charset>` становится простым сбросом | Запись UTF-8 прямо в `src` |
| 16 | `SetUnhandledExceptionFilter` для журнала сбоев | Срабатывает только на настоящие сбои | `AddVectoredExceptionHandler` (ложные срабатывания на штатных исключениях DLL) |
