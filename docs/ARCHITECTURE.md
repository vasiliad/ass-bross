# ДОКУМЕНТ ОПИСАНИЯ АРХИТЕКТУРЫ (SAD - Software Architecture Document)
**Проект:** Сверхлегкий веб-браузер (NanoWeb)
**Платформа:** Windows 10/11 x64
**Язык:** Ассемблер x86-64 (FASM)

## 1. Архитектурная парадигма
Браузер проектируется по паттерну **Event-Driven Single-Process Architecture (событийно-ориентированная однопроцессная архитектура)**.
Вся логика работает в одном главном потоке. Ввод-вывод неблокирующий: события сети и события окна приходят в **один** цикл сообщений Windows, поэтому ожидание сети не блокирует интерфейс.

Ключевые принципы:
* **Собственный движок.** HTML, CSS, компоновка и отрисовка реализуются самостоятельно. Готовые браузерные движки (WebView2, MSHTML) не используются.
* **Без сторонних библиотек.** Разрешены только системные DLL Windows (`kernel32`, `user32`, `gdi32`, `ws2_32`, `secur32`, `mfplat` и т.п.). C-runtime не используется.
* **Изоляция ОС.** Весь платформенно-зависимый код находится в слое HAL. Движок (уровни 2–4) не вызывает WinAPI напрямую — это позволяет тестировать его отдельно и в будущем портировать (Linux, MenuetOS 64).

## 2. Уровни системы (Layered Architecture)

### Уровень 1: HAL — Hardware Abstraction Layer (`src/hal/win64/`)
Обертки над WinAPI. Вызываются через таблицу импорта PE (прямые `syscall` в Windows не используются — номера системных вызовов меняются между сборками ОС).

| Модуль | WinAPI | Назначение |
|---|---|---|
| `SysMem` | `VirtualAlloc`, `VirtualFree` | Резервирование и фиксация памяти для арен |
| `SysNet` | `ws2_32`: `getaddrinfo`, `socket`, `connect`, `send`, `recv`, `WSAAsyncSelect` | TCP-сокеты, события сокетов как оконные сообщения |
| `SysTLS` | `secur32` (SChannel/SSPI) | TLS для HTTPS (после MVP) |
| `SysGUI` | `user32`: `CreateWindowExW`, цикл сообщений; `gdi32`: `CreateDIBSection`, `BitBlt` | Окно, кадровый буфер, ввод мыши и клавиатуры |
| `SysFont` | `gdi32`: `CreateFontW`, `GetTextExtentExPointW`, `ExtTextOutW` | Измерение и вывод текста (TrueType, кириллица, сглаживание) |
| `SysMedia` | Media Foundation (`mfplat`, `IMFMediaEngine`) | Воспроизведение `<audio>`/`<video>` (после MVP) |
| `SysFile` | `CreateFileW`, `ReadFile`, `WriteFile`, `GetStdHandle` | Чтение локальных файлов, отладочный вывод |
| `SysTime` | `QueryPerformanceCounter` | Замер времени (KPI, профилирование) |

### Уровень 2: Core Services (`src/core/`)
* **Memory Allocator** — арены поверх `SysMem` (см. `MEMORY_MODEL.md`).
* **Event Loop** — главный цикл сообщений (см. раздел 4).
* **URL** — разбор URL и разрешение относительных ссылок.
* **NetClient** — собственная реализация HTTP/1.1 поверх `SysNet` (см. раздел 5).
* **Encoding** — определение кодировки и перекодирование в UTF-8.

### Уровень 3: Web Engine (`src/engine/`)
* **HTML Tokenizer** — конечный автомат по спецификации HTML5 (поддерживаемое подмножество — раздел 6). Возобновляемый: хранит состояние и смещение в буфере.
* **DOM Builder** — строит дерево `DOM_NODE` по потоку токенов, применяя правила неявного закрытия тегов.
* **CSS Parser** — разбирает встроенную таблицу стилей браузера (UA stylesheet), блоки `<style>` и атрибуты `style=""` в CSSOM.
* **Style Resolver** — сопоставляет селекторы, применяет каскад (специфичность, порядок, `!important`) и наследование, заполняет `COMPUTED_STYLE`.
* **Layout Engine** — строит Render Tree: блочная компоновка (box model) и строчная компоновка с переносом строк.

### Уровень 4: Presentation (`src/paint/`, `src/ui/`)
* **Painter** — обходит Render Tree и рисует в кадровый буфер (фоны, рамки, текст).
* **UI** — адресная строка, прокрутка, обработка кликов по ссылкам (hit-testing), история навигации.
* **JS Bindings** — не входит в MVP (раздел 9).

## 3. Поток данных (Data Flow)
1. **Input:** пользователь вводит URL или кликает по ссылке → Event Loop запускает навигацию.
2. **Fetch:** `NetClient` асинхронно выполняет HTTP GET; ответ дописывается в `src_arena`. Для `file://` и пути в командной строке данные читаются через `SysFile`.
3. **Decode:** по `Content-Type`/`<meta charset>` документ приводится к UTF-8.
4. **Parse:** `HTML Tokenizer` → `DOM Builder` строят дерево в `doc_arena`. Содержимое `<style>` передаётся в `CSS Parser`.
5. **Style Resolve:** для каждого элемента вычисляется `COMPUTED_STYLE`.
6. **Layout:** в `layout_arena` строится Render Tree с абсолютными координатами.
7. **Paint:** `Painter` рисует видимую часть (с учётом `scroll_y`) в DIB-буфер.
8. **Display:** `BitBlt` выводит буфер в окно.

В MVP разбор начинается после полной загрузки документа. Токенизатор с самого начала пишется возобновляемым, чтобы потоковый разбор (по мере прихода пакетов) добавлялся без переделки.

### Что запускает какие этапы
| Событие | Этапы |
|---|---|
| Навигация | 2 → 8 полностью, сброс всех арен документа |
| Изменение размера окна | `arena_reset(layout_arena)`, 6 → 8 |
| Прокрутка | Только 7 → 8 |
| Наведение / клик | Hit-testing по Render Tree; перерисовка только при изменении |

## 4. Event Loop и отрисовка
* Цикл: `GetMessageW` → `TranslateMessage` → `DispatchMessageW`. Оконная процедура обрабатывает:
  * `WM_SIZE` — пересоздание DIB-буфера, relayout;
  * `WM_PAINT` — отрисовка грязной области и `BitBlt`;
  * `WM_MOUSEWHEEL`, `WM_KEYDOWN` — прокрутка;
  * `WM_LBUTTONDOWN`, `WM_MOUSEMOVE` — ссылки, курсор;
  * `WM_NET` (`WM_APP+1`) — события сокета от `WSAAsyncSelect` (`FD_CONNECT`, `FD_READ`, `FD_WRITE`, `FD_CLOSE`).
* **Перерисовка только по необходимости** (dirty flag + `InvalidateRect`), без постоянных 60 FPS: в покое браузер не потребляет CPU.
* **Двойная буферизация:** DIB-секция служит задним буфером; на экран попадает только готовый кадр. Плавность прокрутки — цель 60 FPS при скролле.
* **DPI:** процесс объявляет `PER_MONITOR_AWARE_V2` (`SetProcessDpiAwarenessContext`). CSS px умножаются на масштаб монитора на этапе компоновки.
* **DNS:** в MVP `getaddrinfo` вызывается синхронно (обычно единицы миллисекунд, ответ кэшируется ОС). После MVP — асинхронный `GetAddrInfoExW` с ожиданием через `MsgWaitForMultipleObjectsEx(MWMO_ALERTABLE)`.

### Painter
* Прямоугольники (фоны, рамки) заполняются собственным кодом (`rep stosd` / SSE2) прямо в пиксели DIB.
* Текст выводится через GDI (`ExtTextOutW`) в контекст той же DIB-секции. Перед прямой записью пикселей после вызовов GDI обязателен `GdiFlush`.
* Порядок отрисовки — порядок обхода дерева (painter's algorithm). `z-index` и позиционирование — после MVP.

## 5. NetClient (HTTP/1.1)
Конечный автомат: `RESOLVE → CONNECT → SEND → RECV_HEADERS → RECV_BODY → DONE | ERROR`.

Поддерживается в MVP:
* `GET`, заголовки `Host`, `User-Agent`, `Accept-Encoding: identity`, `Connection: close`;
* тело по `Content-Length`, `Transfer-Encoding: chunked` или до закрытия соединения;
* редиректы `301/302/303/307/308` (не более 5 подряд);
* загрузка внешних таблиц стилей `<link rel="stylesheet">`.

Не входит в MVP: HTTPS (этап SChannel), сжатие gzip/deflate (собственный inflate), keep-alive, cookies, HTTP/2. Для `https://` в MVP показывается встроенная страница-заглушка с объяснением.

## 6. Поддерживаемое подмножество HTML/CSS в MVP
**HTML:**
* теги, атрибуты (в кавычках и без), комментарии, `<!DOCTYPE>`;
* void-элементы (`br`, `hr`, `img`, `meta`, `link`, `input`…);
* неявное закрытие `<p>`, `<li>`, `<td>`, `<tr>`, `<option>`;
* raw text: содержимое `<script>` пропускается, `<style>` передаётся в CSS Parser;
* сущности: числовые (`&#123;`, `&#x7B;`) и основные именованные (`amp lt gt quot apos nbsp copy mdash laquo raquo`…);
* кодировки: UTF-8, windows-1251.

**CSS:**
* селекторы: `*`, тег, `.class`, `#id`, их сочетание (`div.note`), потомок (пробел), ребенок (`>`), список через запятую;
* свойства: `display` (block, inline, none, list-item), `color`, `background-color`/`background`, `width`, `height`, `margin*`, `padding*`, `border*`, `font-size`, `font-weight`, `font-style`, `text-align`, `text-decoration`;
* единицы: `px`, `%` (для `width`), `em`; цвета: `#rgb`, `#rrggbb`, `rgb()`, именованные (основные);
* каскад: специфичность, порядок, `!important`, наследование (`color`, `font-*`, `text-align`).

Неподдерживаемое свойство или селектор молча пропускаются (как в настоящих браузерах).

## 7. Управление памятью
Стратегия **Arena Allocation** с отдельными аренами для исходника, документа, компоновки и временных данных. Подробности — `MEMORY_MODEL.md`.

## 8. Метрики и KPI
| Метрика | Цель | Как измеряется |
|---|---|---|
| Размер исполняемого файла | < 1.5 МБ (без JS) | Размер `nanoweb.exe` |
| Холодный старт | < 20 мс до первого кадра локальной страницы | `QueryPerformanceCounter`, режим `--stats` |
| Память интерфейса | Private Bytes < 2 МБ без открытой страницы | `GetProcessMemoryInfo` (`PrivateUsage`) |
| Память на документ | < 1 МБ на 1000 DOM-узлов | Размер арен документа |
| Общее потребление | Private Bytes < 20 МБ на тестовом наборе страниц | `--stats`, Process Explorer |
| Прокрутка | 60 FPS на тестовом наборе | Время кадра в `--stats` |
| Простой | 0% CPU без событий | Process Explorer |

> Рабочий набор (Working Set) процесса включает общие системные DLL (`user32`, `gdi32`, `ws2_32` — 3–5 МБ), которые одинаковы для любого Win32-приложения. Поэтому KPI задаются в Private Bytes — памяти, принадлежащей только NanoWeb.

## 9. Долгосрочные направления (после MVP)
* **HTTPS** через SChannel — следующий шаг после MVP: без него недоступна большая часть сайтов.
* **Медиа:** `<audio>` и `<video>` с прямыми ссылками на файлы через Media Foundation (`IMFMediaEngine`). Встроенные декодеры Windows: MP3, AAC, WAV, MP4/H.264; WebM/VP9/AV1 — при наличии расширений из Microsoft Store.
* **Изображения:** PNG, JPEG, GIF через Windows Imaging Component (WIC).
* **CSS:** позиционирование, `z-index`, flexbox.
* **JavaScript (исследовательская цель).** Для современных сайтов, включая YouTube, нужен полноценный движок JS с JIT, полный DOM API, `fetch`, cookies, Media Source Extensions и HTTP/2. Это объём работы, сопоставимый с остальным браузером многократно. Направление не является обязательством; варианты (собственный интерпретатор подмножества JS на ASM или встраивание существующего движка) будут оценены отдельно после MVP.

## 10. Журнал решений
| # | Решение | Причина | Отклонённые варианты |
|---|---|---|---|
| 1 | Платформа — Windows 10/11 x64 | Выбор владельца проекта; ОС даёт окно, TrueType-шрифты, TLS и медиа без сторонних библиотек | Linux (X11/Wayland вручную, свой DNS), MenuetOS 64 (возможен позже как ещё один HAL) |
| 2 | Ассемблер — FASM 1.73 | Нативная поддержка PE64, макросы `proc`/`invoke`/`struct`, сборка без линкера | NASM (нужен внешний линкер) |
| 3 | Соглашение о вызовах — Microsoft x64 везде | Единообразие с WinAPI, вызов функций движка из тестов | Собственное внутреннее соглашение |
| 4 | Только собственный движок | Суть проекта — сверхлёгкий браузер; YouTube — исследовательская цель (раздел 9) | WebView2-оболочка, гибрид с WebView2 |
| 5 | Свой HTTP/1.1 поверх Winsock, HTTPS через SChannel после MVP | Полный контроль над памятью и потоком данных | WinHTTP (запасной вариант, если SChannel окажется слишком трудоёмким) |
| 6 | Текст через GDI | TrueType, кириллица и сглаживание без своего растеризатора шрифтов | Свой bitmap-шрифт, DirectWrite (сложный COM API) |
