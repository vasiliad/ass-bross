# ДОКУМЕНТ ОПИСАНИЯ АРХИТЕКТУРЫ (SAD - Software Architecture Document)
**Проект:** Сверхлегкий веб-браузер (NanoWeb)
**Платформа:** Windows 10/11 x64
**Язык:** Ассемблер x86-64 (FASM)

## 1. Архитектурная парадигма
NanoWeb — **браузер для чтения**: он показывает содержимое страниц в едином аккуратном оформлении (режим чтения), а не воспроизводит дизайн сайтов. Цель — качественный сёрфинг по сайтам с содержимым и максимально быстрый разбор страниц.

Браузер проектируется по паттерну **Event-Driven Single-Process Architecture (событийно-ориентированная однопроцессная архитектура)**. Вся логика работает в главном потоке; события сети и окна приходят в **один** цикл сообщений Windows, поэтому загрузка не блокирует интерфейс.

Ключевые принципы:
* **Собственный движок разбора и отображения.** HTML, режим чтения и отрисовка реализуются самостоятельно. Готовые браузерные движки (WebView2, MSHTML) не используются.
* **Без сторонних библиотек.** Разрешены только системные DLL Windows (`kernel32`, `user32`, `gdi32`, `winhttp`, `ole32`, `windowscodecs`). C-runtime не используется.
* **Сеть — системная (WinHTTP).** Собственные силы тратятся на разбор и отображение, а не на повторную реализацию HTTP и TLS.
* **Изоляция ОС.** Весь платформенно-зависимый код находится в слое HAL. Движок не вызывает WinAPI напрямую — это позволяет тестировать его отдельно и в будущем портировать.

## 2. Уровни системы (Layered Architecture)

### Уровень 1: HAL — Hardware Abstraction Layer (`src/hal/win64/`)
Обертки над WinAPI. Вызываются через таблицу импорта PE (прямые `syscall` в Windows не используются — номера системных вызовов меняются между сборками ОС).

| Модуль | WinAPI | Назначение |
|---|---|---|
| `SysMem` | `VirtualAlloc`, `VirtualFree` | Резервирование и фиксация памяти для арен |
| `SysNet` | `winhttp` (асинхронный режим) | HTTP/HTTPS-загрузка (раздел 5) |
| `SysGUI` | `user32`: `CreateWindowExW`, цикл сообщений; `gdi32`: `CreateDIBSection`, `BitBlt` | Окно, кадровый буфер, ввод мыши и клавиатуры |
| `SysFont` | `gdi32`: `CreateFontW`, `GetTextExtentExPointW`, `ExtTextOutW` | Измерение и вывод текста (TrueType, кириллица, сглаживание) |
| `SysImage` | WIC (`windowscodecs`): `IWICImagingFactory`, `IWICBitmapDecoder`, `IWICBitmapScaler`, `IWICFormatConverter` | Чтение размера и декодирование картинок с уменьшением (раздел 8.1) |
| `SysFile` | `CreateFileW`, `ReadFile`, `WriteFile`, `GetStdHandle` | Локальные файлы, настройки, отладочный вывод |
| `SysTime` | `QueryPerformanceCounter` | Замер времени (KPI, профилирование) |

### Уровень 2: Core Services (`src/core/`)
* **Memory Allocator** — арены поверх `SysMem` (см. `MEMORY_MODEL.md`).
* **Event Loop** — главный цикл сообщений (раздел 4).
* **URL** — разбор URL, разрешение относительных ссылок, шаблоны поиска.
* **Encoding** — определение кодировки и перекодирование в UTF-8.
* **Settings** — чтение `nanoweb.ini`.

### Уровень 3: Web Engine (`src/engine/`)
* **HTML Tokenizer** — быстрый возобновляемый конечный автомат (разделы 6 и 10).
* **DOM Builder** — строит дерево `DOM_NODE`, применяя правила неявного закрытия тегов.
* **Hide Rules** — минимальный разбор CSS сайта: извлекаются **только** правила, скрывающие элементы (`display: none`, `visibility: hidden`), и помечают элементы флагом `NF_HIDDEN` (раздел 7).
* **Reader Layout** — раскладка в режиме чтения: одна колонка, собственные стили по роли элемента, перенос строк. Результат — плоский **список строк** (display list), а не дерево (раздел 8).

### Уровень 4: Presentation (`src/paint/`, `src/ui/`)
* **Painter** — рисует видимые строки в кадровый буфер.
* **UI** — адресная строка, прокрутка, ссылки, история, поиск по странице.

## 3. Поток данных (Data Flow)
1. **Input:** пользователь вводит URL или запрос, кликает по ссылке → Event Loop запускает навигацию.
2. **Fetch:** `SysNet` асинхронно загружает страницу через WinHTTP; порции данных дописываются в `src_arena`. Для `file://` и пути в командной строке данные читаются через `SysFile`.
3. **Decode:** по `Content-Type`/`<meta charset>` документ приводится к UTF-8.
4. **Parse:** `HTML Tokenizer` → `DOM Builder` строят дерево в `doc_arena` по мере прихода данных. Содержимое `<style>` и `style=""` передаётся в `Hide Rules`; внешние таблицы стилей загружаются параллельно (раздел 7).
5. **Images:** для каждого `<img>` создаётся запись `IMAGE`, загрузка картинок идёт параллельно, видимые — первыми (раздел 8.1).
6. **Hide:** элементы, скрытые правилами или атрибутами, помечаются `NF_HIDDEN`.
7. **Layout:** в `layout_arena`/`line_arena` строится список строк с координатами.
8. **Paint:** `Painter` двоичным поиском находит первую видимую строку и рисует видимую часть в DIB-буфер.
9. **Display:** `BitBlt` выводит буфер в окно.

| Событие | Этапы |
|---|---|
| Навигация | 2 → 9 полностью, сброс всех арен документа |
| Изменение размера окна | Сброс `layout_arena` и `line_arena`, 7 → 9 |
| Стал известен размер картинки | 7 → 9 (с сохранением позиции прокрутки) |
| Прокрутка | Только 8 → 9 (+ декодирование картинок, попавших в видимую область) |
| Клик / наведение | Двоичный поиск строки по Y, затем фрагмента по X |

## 4. Event Loop и отрисовка
* Цикл: `GetMessageW` → `TranslateMessage` → `DispatchMessageW`. Оконная процедура обрабатывает:
  * `WM_SIZE` — пересоздание DIB-буфера, relayout;
  * `WM_PAINT` — отрисовка и `BitBlt`;
  * `WM_MOUSEWHEEL`, `WM_KEYDOWN` — прокрутка, горячие клавиши;
  * `WM_LBUTTONDOWN`, `WM_MOUSEMOVE` — ссылки, курсор;
  * `WM_NET` (`WM_APP+1`) — события WinHTTP (раздел 5).
* **Перерисовка только по необходимости** (dirty flag + `InvalidateRect`): в покое браузер не потребляет CPU.
* **Двойная буферизация:** DIB-секция служит задним буфером. Цель — 60 FPS при прокрутке.
* **DPI:** процесс объявляет `system DPI aware` (`SetProcessDPIAware`); размеры шрифтов и отступов умножаются на масштаб при старте.
* **Темы:** светлая и тёмная, по системной настройке Windows.

### Painter
* Фон, горизонтальные линии `<hr>`, полосы цитат и подчёркивания — собственным кодом (`rep stosd` / SSE2) прямо в пиксели DIB.
* Текст — через GDI (`ExtTextOutW`) в контекст той же DIB-секции. Перед прямой записью пикселей после вызовов GDI обязателен `GdiFlush`.

## 5. Сеть: WinHTTP
WinHTTP используется в асинхронном режиме (`WINHTTP_FLAG_ASYNC`). Его колбэк вызывается в служебных потоках WinHTTP, поэтому он **ничего не обрабатывает сам**: только `PostMessageW(hwnd, WM_NET, status, context)`. Это единственный код вне главного потока; вся логика остаётся однопоточной.

Цепочка: `WinHttpOpen` (сессия на весь процесс) → `WinHttpConnect` → `WinHttpOpenRequest` → `WinHttpSendRequest` → `WinHttpReceiveResponse` → `WinHttpQueryHeaders` (статус, `Content-Type`) → цикл `WinHttpQueryDataAvailable` / `WinHttpReadData` прямо в конец `src_arena`.

Включается в сессии:
* HTTPS и проверка сертификатов (при ошибке — встроенная страница предупреждения);
* HTTP/2 (`WINHTTP_OPTION_ENABLE_HTTP_PROTOCOL`);
* автоматическая распаковка gzip/deflate (`WINHTTP_OPTION_DECOMPRESSION`);
* автоматические редиректы;
* cookies (хранятся в памяти сессии WinHTTP до закрытия браузера);
* системный прокси (`WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY`).

Заголовки запроса как у обычного браузера (`User-Agent`, `Accept`, `Accept-Language: ru,en`) — это снижает шанс попасть под антибот-фильтры.

## 6. Поддерживаемый HTML
* Теги, атрибуты (в кавычках и без), комментарии, `<!DOCTYPE>`, void-элементы.
* Неявное закрытие `<p>`, `<li>`, `<td>`, `<tr>`, `<option>`, `<dt>`, `<dd>`.
* Raw text: содержимое `<script>` пропускается, `<style>` передаётся в Hide Rules.
* `<noscript>` **показывается** — JavaScript у нас нет, и сайты кладут туда версию для таких браузеров.
* Сущности: числовые и основные именованные (`amp lt gt quot apos nbsp copy mdash ndash laquo raquo hellip`…).
* Кодировки: UTF-8, windows-1251.
* Восстановление после любых ошибок разметки: на любом входе программа не падает и что-то показывает.

### Роли элементов в режиме чтения
Каждому тегу по статической таблице назначается роль; оформление роли задано в браузере, CSS сайта на него не влияет.

| Роль | Теги | Оформление |
|---|---|---|
| Абзац | `p`, `div`, `section`, `article`, `main`, `header`, `footer`, `nav`, `aside`, `figure`, `form`, `address`, `center` | Блок, отступ между абзацами |
| Заголовок | `h1`–`h6` | Крупнее и жирнее по уровню |
| Список | `ul`, `ol`, `dl`; `li`, `dt`, `dd` | Отступ по уровню вложенности, маркер `•` или номер |
| Цитата | `blockquote` | Отступ и вертикальная полоса слева |
| Преформатированный | `pre` | Моноширинный шрифт, строки переносятся с меткой `↩` |
| Таблица | `table`, `tr`, `td`, `th` | В MVP каждая строка таблицы — одна строка текста, ячейки через `│` |
| Линия | `hr` | Горизонтальная линия |
| Строчные | `a`, `b`, `strong`, `i`, `em`, `code`, `kbd`, `u`, `s`, `del`, `ins`, `sub`, `sup`, `span`, `small`, `mark`, `abbr`, `q`, `cite`, `time`, `label` | Ссылка, жирный, курсив, моноширинный, подчёркнутый, зачёркнутый или без изменений |
| Перевод строки | `br` | — |
| Картинка | `img` | Блоком по ширине колонки (не шире оригинала); картинки уже 64 px — в строке текста (иконки). До загрузки и при ошибке — рамка с текстом `alt` |
| Заменитель | `iframe`, `video`, `audio`, `embed`, `object` → ссылка на источник | Приглушённый цвет |
| Не показывается | `head`, `script`, `style`, `template`, `svg`, `canvas`, `select`, `input`, `textarea`, `button` | — |

Незнакомые теги ведут себя как строчные. Шрифты: основной (Segoe UI) и моноширинный (Consolas). Ширина колонки — около 70 символов, по центру окна.

## 7. Скрытые элементы (Hide Rules)
Режим чтения игнорирует CSS сайта, кроме одного: сайты прячут через CSS мобильные меню, всплывающие окна, cookie-баннеры, служебные тексты. Без учёта этого они станут видны. Поэтому элемент скрывается (`NF_HIDDEN`), если:
* у него атрибут `hidden` или `aria-hidden="true"`;
* его `style=""` содержит `display: none` или `visibility: hidden`;
* под него подходит правило из `<style>` или внешней таблицы стилей с `display: none` или `visibility: hidden`.

Разбор CSS минимальный:
* из всех объявлений нужны только `display: none` и `visibility: hidden`; остальные пропускаются без разбора значений;
* селекторы: `*`, тег, `.class`, `#id`, их сочетание, потомок (пробел), ребёнок (`>`), список через запятую. Правило с непонятным селектором (атрибуты, псевдоклассы) пропускается целиком — лучше показать лишнее, чем спрятать нужное;
* `@media`: учитываются только блоки без условий по ширине или с `screen`/`all`; `print` и условия по ширине пропускаются;
* внешние таблицы стилей (`<link rel="stylesheet">`) загружаются параллельно с разбором, не больше 4 файлов и не больше 512 КБ каждый. Раскладка ждёт их не дольше 300 мс, затем показывает страницу и перекладывает её по приходу.

## 8. Режим чтения (Reader Layout)
* Один проход по DOM в порядке документа. Состояние строчного оформления (жирный, курсив, ссылка, моноширинный) — счётчики вложенности, а не вычисленный стиль на каждый элемент.
* Пробелы схлопываются (кроме `pre`); текст режется на слова и раскладывается по строкам с переносом по ширине колонки. Ширина слов измеряется через `SysFont` с кэшем ширин символов.
* Результат — **плоский массив строк** (`LINE`) в порядке сверху вниз, у каждой строки список фрагментов (`FRAGMENT`: текст, маркер или картинка). Дерева блоков нет: все украшения (маркер списка, полоса цитаты, линия `hr`) привязаны к строкам.
* Поэтому отрисовка видимой части и поиск строки под курсором — двоичный поиск по Y за `O(log n)`, а прокрутка не требует пересчёта.

### 8.1. Картинки
Картинки показываются автоматически (отключается в `nanoweb.ini`: `[images] enabled = 0`).
* **Выбор источника.** Берётся `src`; если в `src` заглушка (`data:`-картинка или пустой GIF), а есть `data-src` / `data-original` / `data-lazy-src` — берётся он: без JS скрипты «ленивой загрузки» не сработают. Из `srcset` выбирается вариант, ближайший к ширине колонки. `data:` URI с base64 декодируются на месте.
* **Загрузка.** Через WinHTTP, до 6 одновременно; первыми — картинки в видимой области. Каждая картинка — в собственную арену (`MEMORY_MODEL.md`, раздел 1.4). Файлы больше 16 МБ не загружаются.
* **Размер до декодирования.** Если у `<img>` есть `width`/`height` — место резервируется сразу. Иначе размер читается из заголовка файла (WIC, без распаковки) сразу после загрузки, и страница перекладывается с сохранением верхней видимой строки.
* **Декодирование** — только для картинок в видимой области и рядом с ней: WIC декодирует **сразу с уменьшением** до отображаемого размера (`IWICBitmapScaler`) в BGRA premultiplied. Фотография 4000×3000 в колонке 800 px занимает 1,9 МБ, а не 48 МБ.
* **Кэш пикселей — 6 МБ**, вытеснение дальних от экрана картинок; повторное декодирование из сжатых байтов.
* **Отрисовка** — собственное альфа-смешивание SSE2 в DIB-буфер.
* **Форматы:** JPEG, PNG, GIF (первый кадр), BMP, ICO; WebP — на Windows 11 или с расширением из Microsoft Store. SVG не поддерживается — показывается `alt`.

## 9. Границы проекта
**Не цели (сознательно исключено):**
* Воспроизведение дизайна сайтов (CSS-вёрстка, цвета и шрифты сайтов).
* JavaScript. Сайты, которые без JS не показывают содержимое (веб-приложения, YouTube, большинство соцсетей), не поддерживаются.
* Аудио и видео.
* Плагины, расширения, синхронизация, WebGL, WebAssembly.

**После MVP:** анимация GIF, формы (`GET`/`POST`), Marginalia через API, история и закладки, вкладки, настоящая сетка для таблиц с данными.

## 10. Производительность разбора
Скорость разбора — ключевое требование проекта:
* **SIMD-сканирование.** Токенизатор пропускает текст и значения атрибутов блоками по 16 байт (SSE2 — есть на любом x64-процессоре), ища только значимые символы (`<`, `&`, `\r`, `\0`, кавычку). Путь AVX2 (32 байта) включается после проверки `CPUID`.
* **Zero-copy.** Токены и текстовые узлы — срезы исходного буфера; копирование только при декодировании сущностей.
* **Bump-аллокация.** Создание узла — сдвиг указателя арены.
* **Идентификаторы вместо строк.** Имена тегов и атрибутов переводятся в числа через совершенную хэш-функцию, генерируемую на этапе сборки.
* **Автомат через таблицу переходов** (`jmp [table + state*8]`).
* **Потоковый разбор** по мере прихода данных из сети.
* **Hide Rules** раскладываются по корзинам по самой правой части селектора (тег / класс / id); для элемента проверяются только подходящие правила.
* **Замеры:** `nanoweb.exe --bench parse|hide|layout <file> [N]` печатает МБ/с и время этапов на корпусе `tests/bench/`. Регрессия скорости больше 5% считается ошибкой.

## 11. Поиск

### 11.1. Поиск из адресной строки
Ввод без схемы (`://`) и без точки считается запросом и подставляется в шаблон (`%s` — запрос в URL-кодировке UTF-8). Шаблоны и префиксы — в `nanoweb.ini`:

```ini
[search]
default = https://lite.duckduckgo.com/lite/?q=%s
w = https://ru.wikipedia.org/w/index.php?search=%s
```
Требование к поисковику — выдача обычным HTML без JavaScript. Google не подходит (с 2025 года требует JS).

**Антибот-защита (проверено 2026-10-01).** DuckDuckGo Lite отвечал простому HTTP-клиенту (curl) капчей с картинками; HTML-выдача Marginalia — промежуточной страницей «Wait a moment». Меры:
1. Заголовки как у обычного браузера; TLS и HTTP/2 через WinHTTP — стандартный сетевой стек Windows.
2. На этапе M4 проверяется, открывается ли DuckDuckGo Lite без капчи. Если капча появляется регулярно — изображения и формы переносятся в MVP.
3. Страница-заглушка (капча, «подождите») распознаётся, браузер предлагает другой поисковик из `nanoweb.ini`.

**После MVP — Marginalia через API** (префикс `m`, «Малый веб»): `GET https://api2.marginalia-search.com/search?query=…&count=20` с заголовком `API-Key` (ключ `public` работает без регистрации, проверено), ответ JSON разбирается собственным минимальным парсером. Marginalia ищет текстовые сайты без JS, которые NanoWeb показывает полностью; минусы — индекс только на английском, проект поддерживает один человек, общий ключ при перегрузке отвечает `503`.

### 11.2. Поиск по странице (Ctrl+F)
* Поиск по фрагментам текста раскладки: совпадение сразу даёт строку и координаты для подсветки и прокрутки.
* **SIMD-поиск подстроки:** первый и последний байт образца сравниваются сразу с 16 (SSE2) или 32 (AVX2) позициями; полное сравнение — только для кандидатов.
* Без учёта регистра для латиницы и кириллицы в UTF-8 (компактная таблица, без полного Unicode).
* Подсветка обновляется на каждый символ; F3 / Shift+F3 — следующее и предыдущее совпадение.

## 12. Метрики и KPI
| Метрика | Цель | Как измеряется |
|---|---|---|
| Размер исполняемого файла | < 1 МБ | Размер `nanoweb.exe` |
